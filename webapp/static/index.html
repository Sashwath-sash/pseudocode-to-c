02 / UNDERSTAND

What happens between source and C?

Each step produces a representation you can inspect in the workspace.

01

Lexical analysis

The lexer splits source into keywords, identifiers, literals and operators, with line and column positions.

lexer.py → tokens
02

Parsing

The parser checks statement structure and builds an abstract syntax tree for expressions and blocks.

parser.py → AST
03

Semantic checks

Names, types and lexical scopes are checked. The symbol table records declarations.

semantic.py → symbols
04

Intermediate code

Expressions become ordered temporary steps; loops and branches stay structured.

ir.py → IR
05

Optimization

Safe integer constants and selected identities are simplified before output.

optimizer.py → optimized IR
06

C generation

The backend emits readable C, including selected runtime guards for risky operations.

cgen.py → C99

03 / REFERENCE

A small language with clear rules.

The syntax is deliberately structured so each compiler stage is visible and explainable.

01

Data

INTEGER, REAL, CHAR, STRING, plus fixed-size one- and two-dimensional arrays.

02

Flow

IF / ELSE, WHILE, inclusive FOR, BREAK, CONTINUE, and typed functions.

03

Operations

Arithmetic, comparisons, short-circuit AND / OR / NOT, integer bitwise operations, READ and PRINT.

04

Checks

Declaration and type errors are caught before C. Division, array bounds and shift counts have targeted generated guards.

Current scope

This is a defined pseudocode language, not free-form English or C input. Pointers, structures and dynamic allocation are not supported. Functions use scalar parameters and returns; arrays have at most two dimensions. STRING values hold at most 255 ASCII characters. General arithmetic overflow and uninitialized use are not automatically checked.
